# 针对网络环境屏蔽  GitHub 22 端口的解决方案

### 方案 1：配置 SSH 强制使用 443 端口连接 GitHub（推荐）

这个方法能保留 SSH 方式的便利，只是把连接端口从 22 换成 GitHub 开放的 443 端口（443 是 HTTPS 端口，几乎不会被屏蔽）。

1. 编辑 SSH 配置文件（没有则新建）：

   ```bash
   # Linux/Mac 系统
   mkdir -p ~/.ssh  # 确保 .ssh 目录存在
   vim ~/.ssh/config
   
   # Windows（PowerShell，以管理员身份运行）
   New-Item -Path $HOME\.ssh\config -ItemType File -Force
   notepad $HOME\.ssh\config
   ```

2. 在配置文件中粘贴以下内容（直接复制即可）：

   ```properties
   Host github.com
     Hostname ssh.github.com
     Port 443
     User git
     IdentityFile ~/.ssh/id_rsa  # 替换为你的私钥路径
     TCPKeepAlive yes
     IdentitiesOnly yes
   ```

   - 注意：`IdentityFile` 行要对应你之前生成的私钥文件名（比如用 `ed25519` 生成的就是 `~/.ssh/id_ed25519`）。

3. 保存并退出编辑器（Vim 按 `Esc` → 输入 `:wq` 保存；记事本直接保存）。

4. 重新测试 SSH 连接：

   ```bash
   ssh -T git@github.com
   ```

   正常情况下会返回：

   Hi 你的用户名! You've successfully authenticated, but GitHub does not provide shell access.

### 方案 2：彻底改用 HTTPS 方式（备用）

如果方案 1 仍有问题，可直接切换到 HTTPS 协议（完全避开 SSH 端口问题）：

1. 查看当前远程仓库地址：

   ```bash
   git remote -v
   ```

2. 将 SSH 地址替换为 HTTPS 地址（替换成你的仓库实际地址）：

   ```bash
   git remote set-url origin https://github.com/你的用户名/你的仓库名.git
   ```

3. 后续拉取 / 推送代码时，Git 会提示输入 GitHub 用户名和「个人访问令牌（PAT）」（而非密码）：

   - 个人访问令牌生成：GitHub → 头像 → Settings → Developer settings → Personal access tokens → Generate new token（勾选 `repo` 权限）。

### 额外排查：确认网络是否真的屏蔽 22 端口

可以执行以下命令验证 22 端口是否通，443 端口是否通：

```bash
# 测试 22 端口（大概率不通）
telnet github.com 22

# 测试 443 端口（大概率通）
telnet ssh.github.com 443
```

- 如果 `telnet` 提示「连接拒绝」，说明端口被屏蔽；
- 如果提示「Connected to...」，说明端口可用。
